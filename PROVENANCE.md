# Evidence policy

Each specification identifies its supported chips, source references, evidence
labels, validation boundary and unresolved behavior. Public documentation,
public source revisions, independent measurements and reproducible test vectors
provide distinct evidence classes.

A register address does not establish every field meaning. Use `inferred` for
unconfirmed interpretations. A hardware result applies only to its identified
chip, configuration and image; it does not accept another implementation.

Protocol requirements and resource profiles describe intended behavior.
Accepted capabilities require matching build, protocol and hardware evidence.
Each result identifies the specification revision, implementation revision,
configuration, test inputs and observed gate. Report failed and untested
requirements explicitly.
